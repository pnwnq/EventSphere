# 更新指令

## README.md 更新规则
1. 总结本次对话的主要内容和讨论要点
2. 更新当前项目进展概述
3. 如有必要，调整下一步开发计划
4. 如有新的操作步骤，请添加到相应部分
5. 确保文档反映项目的最新状态
6. 使用简洁明了的语言，便于团队成员快速理解
7. 如有新功能，请添加其用途、使用方法、参数说明和返回值说明
8. 更新主要特点列表，确保与最新进展一致
9. 更新应用场景，反映新添加的功能

## 其他文档更新规则

### ProjectRequirements.md
1. 如有新的或变更的项目需求，请更新此文档
2. 确保所有需求都清晰、具体、可测试
3. 更新功能列表的完成状态
4. 更新当前进展和下一步计划
5. 如有新的非功能需求，请添加到相应部分

### FunctionalDesign.md
1. 如有新的功能设计或现有功能的变更，请更新此文档
2. 包括UI设计、技术实现方案和测试用例
3. 更新每个模块的当前进展
4. 调整下一步计划以反映最新的开发重点
5. 更新测试用例，确保覆盖新添加的功能

### CodeChangeLog.md
1. 记录所有代码变更，包括新功能添加和bug修复
2. 提供简要但明确的变更说明
3. 更新待办事项列表
4. 按照"添加"、"变更"、"修复"、"待办"等类别组织变更记录

### CursorEfficiencyGuidelines.md
1. 仔细审查对话内容，识别需要更新或添加的新信息、最佳实践或策略
2. 将新内容整合到文档的适当部分，保持文档的结构和逻辑性
3. 如果新内容不适合现有部分，考虑创建新的部分或子部分
4. 更新项目特定指南，反映项目的最新需求和开发重点

## 通用更新原则
1. 仅更新有变化的部分
2. 以markdown格式提供更新后的内容
3. 如果某个文档无需更新，请说明"无需更新"或"文档无需更新"
4. 确保所有文档之间的信息保持一致性
5. 在更新文档时，考虑项目的长期发展和可维护性
6. 使用清晰、简洁的语言，避免歧义
7. 保持文档的结构化和易读性
8. 在更新文档时，考虑是否需要同时更新相关的代码注释

记住，良好的文档更新习惯是保证项目成功的关键因素之一。
